# 组织私有插件目录与插件策略

组织私有插件目录（`/organization/plugin-directory`）管理**仅本组织可见的私有插件版本**：审批、停止分发、恢复送审与回滚都需要「提交 → 另一位管理员审批 → 发起人最终确认」的 **maker-checker** 流程。配套的插件策略包（`/organization/plugin-policies`）以模板+组织副本的形式收紧插件相关 RBAC 权限。两个页面**都没有主导航入口**，只能通过地址栏直接输入访问。

## 适用范围

| 角色                                                     | 目录查看                                               | 目录动作权限                                                                                                        | 策略                                          |
| -------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `org_admin`（含 owner/admin）                            | ✓                                                      | 全权：`plugin_registry:review`（批准）、`:manage`（停止分发/恢复送审）、`:rollback`（回滚）                         | `plugin_install:view/manage`、`org:manage` 等 |
| `project_manager`                                        | ✓                                                      | 查看 + 提交（`plugin_registry:view/submit`）、安装管理（`plugin_registry:*` 提交类 + `PLUGIN_INSTALL_VIEW/MANAGE`） | 只读                                          |
| `member` / `external_collaborator` / `readonly_observer` | 只读（`plugin_registry:view` + `plugin_install:view`） | 无动作按钮（无权限时动作区不渲染）                                                                                  | 只读                                          |

- 无 `plugin_registry:view` 权限时整页不渲染（返回空）；策略页无 `plugin_install:view` 同理。
- **适用版本**：team / enterprise；个人版不显示组织私有插件目录与策略。开发/演示环境的「示例数据」版本仅存在于非生产构建，生产环境不做展示。

## 开始之前

- 记住三条红线（页面原意）：
  1. **提交 ≠ 生效**：目录变更必须经另一位管理员审批 + 发起人最终确认后才落库；「不能审批自己发起的申请」有专门错误码拒绝。
  2. **目录条目 ≠ 安装实例**：目录操作只改目录推荐指针；已安装实例「本次动作不会改动」，停用实例须经独立确认流程。
  3. **策略只会收紧既有 RBAC 权限**，不会放大权限。
- 确认你有对应动作权限（见上表）；无权限的按钮不会渲染。
- 示例数据说明（开发/演示环境）：「标记为『示例数据』的版本由本机示例插件库离线写入，仅用于开发与演示环境；它们不连接任何外部服务，也不会出现在生产环境。」

## 操作步骤

> 目录动作全部走 maker-checker 三步；以下步骤 3 的三步必须顺序完成（提交 → 另一位管理员审批 → 发起人最终确认）。

### 步骤 1：进入目录并筛选

1. 在地址栏输入 `/organization/plugin-directory`（无导航入口、无命令面板项）。
2. 阅读标题「组织私有插件目录」副标题「仅本组织可见的私有插件版本；管理动作须经预览与确认流程。」。
3. 用筛选与排序定位目标版本：状态（全部状态/草稿/待审核/已批准/已拒绝/已弃用/已撤回）、来源（仅开发/测试环境出现：全部来源/仅示例数据/排除示例数据）、排序（最新优先/最早优先/版本从高到低/版本从低到高）。
4. 列表行可展开：状态徽章 + （示例数据徽章）+ pluginIdentity + `v{version}·安装中 n` +（已卸载 n）。空态「暂无可展示的插件版本」。

### 步骤 2：查看详情卡

展开目标版本，核对：状态徽章、宿主兼容（「宿主兼容」/「需兼容审查」）、插件标识、安装中实例、历史卸载、最近审批轮次（「第 n 轮」/「尚无审批记录」）、兼容性摘要（前 12 位 digest）、审查要点（reasonCodes）；「受影响安装（仅目录事实；停用实例须经独立确认流程）」清单列出 pluginId + `v{n}·已启用/未启用/已卸载`（需管理权限才显示）。

### 步骤 3：发起动作（maker-checker 三步）

动作按状态与权限计算：**「批准」**（待审核 + review 权）、**「停止分发」**（已批准/已弃用 + manage 权）、**「恢复送审」**（已撤回 + manage 权）、**「回滚到此版本」**（已批准 + rollback 权）。按钮上方提示：「以下动作均需审批与最终确认后才生效：」

1. **提交**：点击动作按钮（如「批准此版本进入组织目录」）打开对话框：上方「目录条目（本次动作的对象）」与虚线框「组织内已安装实例（本次动作不会改动）」两个分区；回滚时另显示「回滚差异（当前 → 目标）」：推荐版本/清单摘要/制品摘要/兼容性摘要的前后 diff + 权限差异（「新增 {key}」/「移除 {key}」/「无净变化」）。存在阻断项时红框提示「存在阻断项，无法提交回滚：」（回滚目标未批准/完整性不完整/不兼容/权限提升/缺失 5 类中文原因）。点击「提交批准申请」。
2. **另一位管理员审批**：提交后状态变为「申请已提交，尚未生效。需由另一位管理员审批，再由持有管理权限者完成最终确认后才会改动目录。」——换一个管理员账号（不能用发起人自己，否则报 `plugin-change-self-approval-denied`「不能审批自己发起的申请，请由另一位管理员审批。」）完成审批。
3. **发起人最终确认**：审批通过后为你签发**一次性确认凭据**：「已签发一次性确认凭据，仅可使用一次；离开本页需重新发起。」点击「**最终确认并生效**」。
4. 生效：页面提示「已生效。目录条目已更新；已安装实例未发生任何改动。」——目录推荐指针已切换，实例零改动。

> [!CAUTION]
> 一次性凭据离开页面即失效：中途刷新/关闭页面后需重新发起整个流程。目录变更期间若条目被他人改动，会收到 `plugin-change-stale`「目录条目在此期间发生变化，请关闭后重新发起。」；若申请已被处理，会收到 `plugin-change-already-decided`「该申请已处理完毕，无需重复确认。」。三种情形都只需重新发起。

### 步骤 4：管理插件策略包（/organization/plugin-policies）

1. 在地址栏输入 `/organization/plugin-policies`，查看头部状态徽章：「生效中 · {bundleId} v{activeVersion}」/「已停用」/「未启用组织策略」。
2. 三张内置模板卡：`admin-managed`（管理员管理）/ `pm-enabled`（项目经理可用）/ `member-readonly`（成员只读）——每张卡有「**复制为组织副本**」按钮（需 manage 权限）。
3. 复制后出现在「组织副本」表：副本 / 版本 / 来源模板 / 摘要 digest / 操作（启用/停用按钮随激活态切换）。
4. 启用/停用后查看「最近一次请求的影响摘要」：动作（复制/启用/停用/升级）、状态、审批（必需/非必需 + 审批人），四个格（受影响角色 / 受影响操作 / 新增目标 / 移除目标）；说明「确认前现有决策保持不变。」
5. 底注（页面原文）：「说明：策略只会收紧既有 RBAC 权限；写操作需经统一变更流审批并由发起人确认后才会生效。」——策略写操作同样返回 requestUid 走审批+确认，不是即时生效。

## 验证结果

- 目录列表/详情/筛选正确；动作按钮仅在你有对应权限时出现。
- maker-checker 三步可走通：提交 → 另一管理员审批 → 一次性凭据 → 最终确认 → 「已生效。目录条目已更新；已安装实例未发生任何改动。」
- 自审批被拒（`plugin-change-self-approval-denied`）；并发变更被拒（stale/already-decided）后重新发起可成功。
- 策略副本启用/停用后影响摘要展示受影响角色/操作/目标；写操作经统一变更流后生效。
- 生产构建中不出现「示例数据」来源与徽章。

## 常见问题

**症状：页面空白/无内容。**
原因：无 `plugin_registry:view`（目录）或 `plugin_install:view`（策略）权限时整页不渲染。
处理：确认角色与组织；`project_manager` 与成员有目录只读权限，动作按钮视权限显隐。

**症状：提交后提示「不能审批自己发起的申请」。**
原因：maker-checker 要求审批人与发起人不同。
处理：请另一位管理员（如另一 `org_admin` 账号）登录完成审批；随后由你（发起人）用一次性凭据最终确认。

**症状：最终确认时提示「目录条目在此期间发生变化，请关闭后重新发起。」**
原因：期间被他人改动（`plugin-change-stale`）。
处理：关闭对话框重新发起整个流程（提交 → 审批 → 确认）。

**症状：回滚被「存在阻断项」拦截。**
可能原因：回滚目标未获批准 / 完整性不完整 / 不兼容 / 权限提升 / 缺失（5 类阻断原因之一）。
处理：按红框列出的原因修复（如目标版本需先批准、补齐制品完整性）后重试。

**症状：点击「回滚」没有逐实例降级向导。**
说明：当前目录工作台只切换目录推荐指针；**不提供**逐实例降级/回滚向导——已安装实例不受目录动作影响，停用实例须经独立确认流程。

**症状：策略启用后权限没有立刻变化？**
说明：策略写操作经统一变更流（审批 + 发起人确认）后才会生效；生效前「现有决策保持不变」。
处理：查看「最近一次请求的影响摘要」中的审批状态；确认后生效。

## 安全与限制

- 所有目录/策略写操作走统一变更流：提交 → 另一位管理员审批 → 发起人一次性凭据确认 → 落库；自审批被拒。
- 目录动作不改动已安装实例；实例停用须经独立确认流程；回滚仅切换推荐指针，无逐实例降级向导。
- 策略只收紧、不放大 RBAC 权限；写操作经统一变更流审批并由发起人确认后生效。
- 示例数据种子仅存在于开发/演示环境（生产构建静态消除）；示例数据不连接外部服务。
- 页面无导航入口（URL 直达）；跨组织数据不可见；判定以服务端 RBAC 为准。
