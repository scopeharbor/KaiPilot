# 繁体模式下部分界面仍显示简体

把界面文字切换为「台湾繁体」或「香港繁体」后，个别区域仍显示简体，多数情况属于**转换机制的设计边界**（元素刻意不转换、用户数据不转换）或**运行时转换延迟**；按本页识别文字类型后即可判断是否需要处理。

## 适用范围

- **适用角色**：全部六类角色——`system_admin`、`org_admin`、`project_manager`、`member`、`external_collaborator`、`readonly_observer`。变体切换是个人偏好，与角色和权限无关。
- **所需权限**：无需任何权限；切换入口位于登录页右上角与「设置 → 个人资料 → 界面文字」。
- **适用版本**：free / team / enterprise（界面变体行为一致）。
- **说明**：本页只涉及**界面显示**层的文字变体；任何文本的**存储与数据内容**都不受变体影响，简体数据永远是简体。

## 开始之前

- **三种变体**：简体中文（默认）、台湾繁体、香港繁体。
- **转换机制**：界面文案由 OpenCC 转换并叠加术语覆写（glossary）渲染为繁体；转换作用于**界面静态文案**（按钮、标题、提示、占位符等），在渲染层完成。
- **实测示例**：登录页「回到你的项目工作台」切换台湾繁体后显示为「回到你的專案工作臺」（台→臺）；「邮箱 / 密码 / 登录」变为「郵箱 / 密碼 / 登入」。
- **变体存储**：偏好保存在浏览器 `localStorage`（key `aiproj-text-variant`，简体 = 未设置或该值为简体）；登录页右上角的文字变体切换不影响登录流程。
- **准备信息**：当前变体设置值、仍显示简体的页面与元素位置、该文字是界面文案还是你或他人录入的数据。

## 症状识别

- **局部未转换**：整页是繁体，但某个按钮、提示或区块仍是简体。
- **数据未转换**：项目名、任务标题、用户名、评论、描述等仍保持录入时的简体。
- **切换后未生效**：刚切换变体，部分文字仍是简体。
- **特定元素始终是简体**：某些品牌词、术语、代码/标识符在繁简两种变体下长得一样或刻意保持简体。

## 排查步骤

### 步骤 1：确认当前变体设置与生效范围

1. 打开「设置 → 个人资料」，在「界面文字」卡片确认选中项（简体中文 / 台湾繁体 / 香港繁体）；也可以在登录页右上角用文字变体切换按钮快速切换。
2. 切换后**刷新页面**（或重新进入该页），让静态文案重新渲染。
3. 确认问题页面是否与登录页属于同一变体来源：变体为全局界面偏好，页面本身没有独立变体设置。

### 步骤 2：判断文字类型（决定是否需要处理）

把「仍显示简体」的文字分为三类，只有第三类可能需要你操作：

| 类型           | 判断方法                                                                 | 是否预期                                                                     | 处理                                       |
| -------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------ |
| 界面静态文案   | 按钮、标题、提示、占位符等产品文案                                       | 应转换                                                                       | 若未转换，见步骤 4 与 5                    |
| 用户数据文本   | 项目名、任务标题、用户名、评论、描述、附件名等**由用户录入或生成的数据** | **预期不转换**——变体只作用于界面文案，数据按录入原样显示与存储               | 无需处理；如需繁体内容，请在录入时使用繁体 |
| 刻意排除的元素 | 用浏览器开发者工具选中该元素，检视其 DOM 属性是否带 `data-no-cc` 标记    | **预期不转换**——带该标记的元素刻意不参与转换（如品牌名、术语、代码、标识符） | 无需处理，这是设计行为                     |

> 判断技巧：把鼠标移到文字上，若它是你（或别人）录入的内容（如任务名、评论），就属于「用户数据」，**界面变体不会也不能改写业务数据**——这既是显示层限制，也是数据一致性要求。

### 步骤 3：观察「运行时转换」是否只是延迟

- 程序动态拼接的字符串（如「共 N 项」「已选 N 条」这类由代码在运行时组装的文案）在**运行时转换层**完成转换，可能因异步渲染、局部刷新而**偶有延迟**。
- 处理：等待页面本轮渲染完成，或刷新页面；延迟属于瞬时现象，刷新后应完成转换。
- 如果刷新后**依然**是简体且不属于用户数据、也不带 `data-no-cc` 标记，进入步骤 4。

### 步骤 4：重置变体偏好后重试

1. 把「界面文字」切回 **简体中文**，刷新页面。
2. 再切回目标变体（台湾繁体 / 香港繁体），刷新页面。
3. 仍异常时，清除该站点 `localStorage` 中 `aiproj-text-variant` 的值后重新设置（具体路径因浏览器而异；不清除其他站点数据）。

### 步骤 5：对照本页判定结论并升级

| 结论                 | 依据                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| 预期行为（无需处理） | 文字是用户数据，或元素带 `data-no-cc` 标记                                         |
| 已验证转换正常       | 刷新/重新切换后静态文案完成转换                                                    |
| 疑似产品缺陷         | 静态界面文案在反复刷新、重置变体后仍为简体，且无 `data-no-cc` 标记、不属于用户数据 |

疑似缺陷时记录信息升级反馈（见下节）；请勿通过反复切换或强制刷新之外的方式尝试「修复」，也不要把此问题当作数据问题处理。

## 修复与恢复

| 症状                   | 直接修复动作                                           |
| ---------------------- | ------------------------------------------------------ |
| 切换后部分文案未生效   | 刷新页面或重新进入该页                                 |
| 动态拼接文案短时未转换 | 等待渲染完成或刷新一次（瞬时延迟）                     |
| 用户数据显示简体       | 无需处理；录入繁体内容才会显示繁体                     |
| 特定元素始终简体       | 检查是否带 `data-no-cc` 标记；带标记即设计行为         |
| 反复刷新仍异常         | 重置变体（简体 → 目标变体）后重试；仍异常按步骤 5 升级 |

## 升级与收集信息

仍确认是界面文案未转换时（排除用户数据与 `data-no-cc` 后），记录：

- 当前变体设置（简体中文 / 台湾繁体 / 香港繁体）与 `localStorage` 中 `aiproj-text-variant` 的值。
- 页面路径、未转换文字原文与所在区域（按钮/标题/提示等）。
- 开发者工具中该元素的 DOM 检视结果（确认无 `data-no-cc` 标记）。
- 发生时间与浏览器/设备信息；**不要提交含敏感数据的截图**。

## 验证结果

- 静态界面文案在目标变体下正确显示繁体（如登录页「登入」「郵箱」「專案工作臺」）。
- 你能区分预期不转换的文字（用户数据、`data-no-cc` 元素）与需要上报的问题。
- 动态拼接文案在刷新后完成转换；数据存储内容未发生任何改变。

## 常见问题

**症状：登录页是繁体，进入项目后有些按钮还是简体。**
可能原因：页面文案渲染时机不同，或涉及动态拼接文案的延迟。
排查与修复：刷新项目页；仍异常确认是否属于用户数据/带 `data-no-cc` 标记。

**症状：项目名、任务标题为什么不转换？**
可能原因：这些是业务数据，不是界面文案。
排查与修复：无需处理；变体只作用于界面文案，不会改写业务数据。

**症状：切换变体后立即查看，一半文案没变。**
可能原因：运行时转换延迟或渲染未完成。
排查与修复：等待片刻或刷新页面；系统不会要求你在切换后等待固定时长。

**症状：某些文字在繁简两种变体下看起来一样。**
可能原因：该词经转换后字形相同（繁简同形词），或元素刻意不转换。
排查与修复：对照同页面其他文案判断；带 `data-no-cc` 的元素属预期行为。

**症状：台湾繁体与香港繁体有什么差别？**
说明：系统提供两个繁体变体选项，按 OpenCC 对应规则与术语覆写呈现；个别用词存在地域差异属正常呈现，不是未转换。

**症状：切换变体会影响数据吗？**
不会。变体只改变界面显示；存储中的数据（包括用户以简体录入的内容）始终保持原样，繁简切换不产生任何数据变更。

## 安全与限制

- 变体是**界面显示层**能力：不转换用户数据、不转换带 `data-no-cc` 标记的元素，这是设计边界，不是可配置开关。
- 变体偏好存于浏览器本地（`localStorage`），换设备/换浏览器后需要重新设置；不会随账号同步到其他设备。
- 变体不影响登录、权限与数据安全；任何与文字变体相关的排查都不涉及密钥与令牌。
