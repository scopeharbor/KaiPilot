# 项目加载失败与列表为空

项目列表为空、加载失败、无权限访问项目或进详情页报「项目不存在」时，按本页依次排查：多数情况由组织选择、角色权限、列表筛选或临时网络问题引起。

## 适用范围

- **适用角色**：六类角色全部适用——`system_admin`、`org_admin`、`project_manager`、`member`、`external_collaborator`、`readonly_observer`。其中 **external_collaborator 与 readonly_observer 只能看到被明确授权（加入成员列表）的项目**；项目经理与组织管理员在处理成员访问问题时参考本页。
- **所需权限**：查看项目列表需要 `project:view`（六角色均默认具备）；「新建项目」按钮需要 `project:create`（侧栏「项目列表」入口也按 `project:view` 展示层过滤，**服务端判定才是安全边界**）。
- **适用版本**：free / team / enterprise。

## 开始之前

- **项目按组织隔离**：列表只显示当前组织下你有权查看的项目；跨组织项目一律不可见。
- **列表默认排除已归档项目**：状态筛选默认「全部状态」不包含 `已归档`（独立的「已归档」筛选项可用）。
- **准备信息**：当前所在组织、期望看到但缺失的项目名或编码、错误表现与发生时间。

## 症状识别

- **项目列表为空**：登录后「项目」页没有任何项目（或只有部分项目）。
- **加载失败**：列表区域出现错误提示，或加载动画长时间不结束。
- **无权限提示**：整页提示「无权访问项目」，或进项目详情被拒。
- **项目不存在**：通过链接/搜索进入某个项目时返回「项目不存在」。
- **筛选后为空**：有搜索词或状态筛选时「没有匹配的项目」。

## 排查步骤

### 步骤 1：判断页面提示对应哪一类原因

项目页的错误提示与原因一一对应：

| 页面提示                                            | 含义                                 | 处理                                                                                          |
| --------------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------- |
| 「请先选择组织」                                    | 当前账号未选择或未加入任何组织       | 在右上角组织选择器加入/切换到目标组织                                                         |
| 「无权访问项目」                                    | 当前账号没有 `project:view` 权限     | 联系组织管理员核对成员角色与附加权限                                                          |
| 「项目加载失败」「请稍后重试，或检查网络连接。」    | 接口请求失败（网络、服务或代理问题） | 见步骤 4                                                                                      |
| 「还没有项目」                                      | 当前组织内确实还没有项目（空态）     | 有 `project:create` 权限时点「新建项目」创建第一个项目                                        |
| 「没有匹配的项目」+「调整搜索词或状态筛选后再试。」 | 搜索词或状态筛选无命中               | 清空搜索词、切换状态筛选（8 项：全部状态/草稿/计划中/进行中/暂停/已完成/已取消/已归档）后重试 |

### 步骤 2：核对组织与成员资格

1. 确认右上角组织选择器中的组织正确：项目属于组织，**换了组织就看不到原组织的项目**。
2. 确认你在目标项目「成员管理」中：external_collaborator 与 readonly_observer 只有在成员列表里才能看到项目；不在列表中的项目对你不可见。
3. 组织成员角色映射到 `org_admin / member / readonly_observer`，项目内角色映射到 `project_manager / member / external_collaborator / readonly_observer`；**两级权限取交集**——组织无权限时项目内权限不生效。
4. 权限调整后如果仍看不到：退出重登一次，让会话重新加载角色快照。

### 步骤 3：排查「项目不存在」（详情页 404）

- 详情接口对「不属于当前组织」与「真的不存在」**统一返回 404「项目不存在」**，不泄露项目是否存在——这是组织隔离的安全设计，不是文案错误。
- 处理：确认项目链接中的项目 id 与当前组织匹配；用侧栏「项目列表」重新进入，不要依赖外部保存的旧链接。

### 步骤 4：排查网络与服务

1. 刷新页面；确认网络正常、代理/VPN 未拦截请求。
2. 本机 `pnpm dev` 环境：确认后端已启动（`curl http://localhost:3333/api/v1/health/ready` 应返回 200 且 `checks.database.status=up`）。
3. Docker Compose 环境：`docker compose ps` 确认 frontend / backend / edge 健康；`docker compose logs -f backend` 查看错误日志。
4. 浏览器开发者工具 Network 面板记录接口返回（错误码、request id），供升级排查使用。

### 步骤 5：核对筛选条件与分页

- 列表每页 10 条：项目总数多于 10 时在底部翻页（「第 {page} / {totalPages} 页」），不要把第 1 页当成全部。
- 已归档项目默认不显示：想找归档项目，用状态筛选选「已归档」，或确认该筛选是否支持含归档的查询（新列表接口默认排除归档，`includeArchived` 生效时除外）。
- 搜索框按「名称或编码」匹配：编码不含中文，确认输入内容与项目编码一致。

## 修复与恢复

| 症状               | 直接修复动作                                                            |
| ------------------ | ----------------------------------------------------------------------- |
| 组织错误           | 切换右上角组织后重新查看列表                                            |
| 无权限             | 项目负责人把你加入项目成员列表，或组织管理员调整角色/附加权限后重新登录 |
| 项目不属于当前组织 | 切换到项目所属组织；跨组织访问一律 404，不要尝试绕过                    |
| 网络 / 服务问题    | 刷新或稍后重试；本机环境重启前后端，容器环境检查容器健康                |
| 筛选导致为空       | 点「清除筛选」或重置状态筛选                                            |
| 列表确实为空       | 确认组织内无项目后，用「新建项目」创建第一个项目                        |

## 升级与收集信息

仍失败时，记录以下信息反馈到帮助中心「故障排查」：

- **request id**：错误信息 / 开发者工具网络面板中的请求标识。
- 所在组织、期望访问的项目名或编码、错误提示原文、复现路径。
- 账号的角色信息（组织角色 + 项目角色），**不要提供密码或令牌**。

## 验证结果

- 你能在当前组织下看到全部有权访问的项目；筛选、翻页正常。
- 「项目加载失败」「无权访问项目」等错误态消失。
- 跨组织链接不再出现「项目不存在」以外的歧义提示（404 属预期）。

## 常见问题

**症状：项目列表刷新后仍然为空。**
可能原因：组织选择错误、组织内尚无项目，或已归档项目被默认排除。
排查与修复：切换组织核对；确认组织内是否创建过项目；用状态筛选确认归档项目。

**症状：能看到列表但进不去某个项目。**
可能原因：该项目对你未授权，或链接属于其他组织。
排查与修复：请项目负责人添加你为成员；从列表内链接进入项目；角色判定以服务端为准。

**症状：项目页一直显示「项目加载失败」。**
可能原因：网络、后端服务或代理问题。
排查与修复：刷新；检查后端启动状态（本机 `pnpm dev`）或容器健康；检查代理是否拦截 `/api/v1` 请求。

**症状：详情页提示「项目不存在」，但项目明明存在。**
可能原因：项目属于其他组织，或链接已过期。
排查与修复：从「项目列表」重新进入；确认右上角组织与项目归属一致；系统对跨组织与不存在统一返回 404，属预期行为。

**症状：新建项目按钮不可见。**
可能原因：当前角色没有 `project:create` 权限。
排查与修复：联系组织管理员调整角色；`org_admin`、`owner` 具备该权限。

## 安全与限制

- **组织隔离是第一层边界**：所有项目查询自动附加当前组织过滤；跨组织项目 404，不暴露存在性。
- **权限判定在服务端完成**：前端隐藏入口只是 UX，真正门禁是 RBAC Policy；界面提示只用于引导。
- **归档默认隐藏**：列表默认排除已归档项目，使用「已归档」筛选查看。
