# 流式进度不更新（SSE）

AI 草案生成与长回答依赖 SSE 流式通道；进度不更新、心跳超时、断流时，先了解自动重连与进度游标恢复机制，再按网络、代理、部署顺序排查。

## 适用范围

- **适用角色**：使用 AI 流式能力（AI 快速创建、草案生成、Copilot 长回答）的成员（`member`、`project_manager`、`org_admin` 等）；系统管理员（`system_admin`）配合检查后端日志与容器环境。
- **所需权限**：查看与操作跟随对应 AI 能力入口的既有权限；本文是纯排查指引，不新增权限要求。
- **适用版本**：free / team / enterprise；本机 `pnpm dev` 与 Docker Compose 两种部署形态的行为差异见步骤 4。

## 开始之前

- **SSE 是单向长连接**：代理/防火墙空闲超时、弱网、后端服务异常、模型响应慢，都会表现为「进度不动」。
- **已知的自动恢复机制**（先了解，避免误操作）：
  - 静默看门狗：流式通道 **20 秒**收不到新数据视为停滞，前端开始自动重连（最多 **3 次**，退避 1s / 2s / 4s）。
  - 健康徽章随状态变化：`实时连接 / 生成用时较长 / 连接暂时停滞 / 正在恢复连接 / 正在同步进度 / 需要重试`。
  - 进度游标：刷新页面后经 `sessionStorage` 中的游标（key `aiproj-ai-draft-progress-cursor-v1`，24 小时有效，只存低敏标识）自动续传，**不必从头生成**。
- **准备信息**：功能入口、卡住时的画面（健康徽章/进度模块）、网络环境（是否代理/VPN）、部署形态。

## 症状识别

- **进度不更新**：生成任务长时间停在同一步，健康徽章停在「连接暂时停滞」或转「需要重试」。
- **心跳/静默超时**：20 秒无新数据触发看门狗；多次重连失败后提示「进度无法自动恢复，需要您操作重试。」。
- **中途断流**：实时输出收到部分内容后停止。
- **后台任务中断**：提示「后台生成任务已中断，请重新生成草案。」——服务端任务已终止，无法续传。
- **环境差异**：本机正常但容器环境卡住，或只有长回答会断。

## 排查步骤

### 步骤 1：区分「可自动恢复」与「需要操作」

| 提示                                           | 状态                               | 应做动作                                                                                                                       |
| ---------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 「进度连接暂未收到新数据，正在尝试恢复连接。」 | 自动重连中（≤3 次，1s/2s/4s 退避） | 等待，不要刷新                                                                                                                 |
| 「进度连接已中断，可从上次位置继续。」         | 重连失败，但可从上次位置继续       | 刷新页面，游标自动续传；或点「继续接收进度」                                                                                   |
| 「进度无法自动恢复，需要您操作重试。」         | 需要操作                           | 用「继续接收进度 / 重试生成 / 重新生成」恢复；**重试会开始新的生成尝试，之前提供的信息会保留，草案仍需人工审查确认后才能导入** |
| 「后台生成任务已中断，请重新生成草案。」       | 服务端任务终止                     | 点「重新生成草案」                                                                                                             |

> 注意：刷新页面前先确认页面是否已给出「需要您操作重试」；刷新依赖游标续传，游标只存低敏标识（24 小时有效），过期后无法续传，需要重新生成。

### 步骤 2：排查网络与代理

1. 确认代理/VPN 未断开长连接：很多企业代理与防火墙对空闲长连接有超时策略，流式通道空闲即被掐断——表现为「进度不动但页面不报错」。
2. 确认放行策略：放行或缩短代理链，调大空闲超时；SSE 通道需要保持空闲连接不被回收。
3. 弱网环境避免超长生成；可用「实时输出」面板确认最后收到内容的时间点，判断停滞位置。

### 步骤 3：检查模型侧与后端服务

1. 模型响应慢或供应商侧超时同样表现为无进度：参考「AI 生成中断与失败」核对连接、余额与模型可用性。
2. 本机 `pnpm dev`：确认后端已启动（`curl http://localhost:3333/api/v1/health/ready` 200）；看后端日志是否有生成任务异常。
3. 收集后端日志时间窗（有权限时），定位断流时刻服务端是否有报错。

### 步骤 4：检查部署差异（Docker Compose 环境）

- 拓扑提醒：容器部署下 UI / REST / SSE / WebSocket 全部经 `edge`（nginx）同源转发到 backend（3333）；流式特别容易断时，优先检查 edge 与 backend 日志：
  - `docker compose ps`：全服务 healthy（edge / frontend / backend / migrate / postgres / redis）。
  - `docker compose logs -f backend`：看生成任务阶段与报错。
  - `docker compose logs edge`：看连接记录与被切断的连接。
- 常见定位：空闲超时过短或内存/连接数限制导致长连接被回收；调整后 `docker compose restart backend` 重试。
- 健康契约：`/api/v1/health/live`（存活）、`/api/v1/health/ready`（就绪，要求数据库 up）、`/api/v1/health`（综合，数据库 down 时仍 200 degraded）——排查时先确认 ready 通过。

### 步骤 5：按场景分治

| 场景                       | 处理                                                          |
| -------------------------- | ------------------------------------------------------------- |
| 只有长回答会断，短问答正常 | 单次流式时长超过空闲超时：拆分问题/调整代理超时，必要时换模型 |
| 本机正常但容器断           | 检查 edge 空闲超时与 backend 资源限制，参考部署文章           |
| 所有流式都不动             | 先测连接与余额，再查后端服务与网络                            |

## 修复与恢复

| 症状             | 直接修复动作                                          |
| ---------------- | ----------------------------------------------------- |
| 自动重连中       | 等待（1s/2s/4s 退避，最多 3 次）                      |
| 重连失败         | 刷新页面续传（游标 24h 有效）或点「继续接收进度」     |
| 反复断流         | 放行长连接、调大代理空闲超时；拆分输入、切换模型      |
| 后台任务中断     | 重新生成草案（输入信息保留）                          |
| 容器环境断流     | 检查 edge/backend 日志与超时配置，重启 backend 后重试 |
| 游标过期无法续传 | 重新生成；避免长时间搁置后刷新                        |

## 升级与收集信息

仍失败时，收集以下信息反馈到帮助中心「SSE」：

- **request id** 与发生时间。
- 健康徽章演变（停滞 → 重连 → 需要重试）与最后收到内容的时间点。
- 网络环境描述（是否代理/VPN、有无空闲超时策略）、部署形态（本机/容器）。
- 后端日志时间窗（有权限时），**日志中如含令牌请先脱敏**。

## 验证结果

- 流式进度持续更新直到完成：健康徽章保持「实时连接」，9 个模块依次完成。
- 断流场景能通过自动重连或游标续传恢复，草案可正常审查确认。
- 不再出现静默超时中断；长回答也能完整输出。

## 常见问题

**症状：进度条不走但页面没报错。**
可能原因：SSE 通道被代理静默切断（空闲超时）。
排查与修复：检查代理/防火墙长连接策略；刷新后用游标续传；仍失败参考部署文章调大超时。

**症状：提示「进度无法自动恢复，需要您操作重试。」**
可能原因：自动重连 3 次均失败或服务端不再推送。
排查与修复：点「继续接收进度」或「重试生成」；先提供的信息会保留。

**症状：容器部署下流式特别容易断。**
可能原因：edge 空闲超时或 backend 资源/连接限制。
排查与修复：调大超时与资源限制，查看 edge/backend 日志；参考 Docker Compose 部署文章。

**症状：刷新后从最开始生成。**
可能原因：进度游标缺失或已过期（sessionStorage 被清、超过 24 小时、换了浏览器）。
排查与修复：确认同一浏览器、未清理站点数据；游标属低敏标识，过期后只能重新生成。

**症状：只有长回答会断，短问答正常。**
可能原因：单次流式时长超过空闲超时。
排查与修复：拆分问题或调整代理超时；必要时切换模型。

## 安全与限制

- 流式内容按组织隔离；AI 输出不自动落库，需人工确认。
- 进度游标只存低敏标识（sessionStorage，24h TTL），不包含内容与密钥。
- 排查时提供的日志与信息先脱敏；不包含密钥、令牌与敏感输入。
