# OCR 识别异常

图片识别提示「没有可用 OCR 模型」、上传被拒、识别乱码或结果与图片不符时，按本页排查模型配置、图片格式与图片质量；**任何识别结果都必须人工确认后才可使用**。

## 适用范围

- **适用角色**：使用 OCR 能力（图片转文字、文档智能化）的成员（`member`、`project_manager` 及以上）；**组织管理员负责 OCR 模型连接配置**（管理连接需 `ai:connection:manage`）。
- **所需权限**：OCR 预览入口位于「设置 → AI 连接」页的「OCR 预览候选」区（页面对有 `ai:connection:manage` 或 `ai:trigger` 的登录用户可见）；实际使用入口随文档/文件场景按产品既有权限执行。
- **适用版本**：free / team / enterprise。
- **前置说明**：OCR 是独立 AI 模型能力选项，建议单独配置一个带 OCR 能力的模型连接，与对话模型分离管理。

## 开始之前

- 认识「OCR 预览候选」：这是当前 OCR 配置入口的实际位置——下拉框列出**已启用 + 已保存密钥的连接中具备 OCR 能力的模型**，选模型后上传图片点「运行 OCR」查看提取结果。**预览只返回候选数据，不写正式的 OCR 记录。**
- 图片约束：支持 PNG / JPG / WebP，大小 ≤ 2MB；多页文档需逐页处理。
- 红线：识别结果必须在人工确认后才进入业务数据；不自动写入任何字段。

## 症状识别

- **没有可用 OCR 模型**：OCR 模型下拉为空，提示「没有可用 OCR 模型」。
- **上传被拒**：提示「图片过大」「图片格式无效」或「图片读取失败」。
- **识别乱码**：识别文本大量错字、符号或无意义内容。
- **结果不正确**：识别出文字但与图片明显不符（漏行、错段、错数字）。
- **连接失败**：提示服务不可用、超时或模型不存在。

## 排查步骤

### 步骤 1：排查「没有可用 OCR 模型」（最常见）

OCR 候选模型 = 启用状态 + 已设 API Key + 模型具备 OCR 能力，三者缺一都会导致下拉为空。进入「设置 → AI 连接」逐项核对：

| 检查项                | 界面表现                                                    | 处理                                                                                 |
| --------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 连接是否启用          | 连接卡带「(已停用)」标记                                    | 在连接编辑中点「启用」                                                               |
| 是否已保存密钥        | 卡片显示「未设 key」                                        | 编辑连接填入 API Key 并保存（密钥只存后端加密服务，不回显明文）                      |
| 模型是否勾选 OCR 能力 | 连接模型的能力列表中无「OCR」                               | 编辑模型，勾选「OCR」能力                                                            |
| 是否有任何连接        | 列表空态「尚无连接,点「新增连接」添加你的第一个 AI 模型。」 | 新增连接：搜索 models.dev 目录或手动填写协议/Base URL/密钥/模型，勾选 OCR 能力后保存 |

> 提示：未连接真实 OCR 模型的本地环境里，「文档智能」等场景的 OCR 维度会如实地显示「不适用」——这是未配置的真实呈现，不是故障。真实 OCR provider 接入需单独授权，配置前请与组织管理员确认。

配置完成后再回到「OCR 预览候选」：下拉框应出现 `{连接} / {模型}` 候选项，选模型 + 选图片 + 「运行 OCR」应正常返回提取结果。

### 步骤 2：核对图片格式与大小

上传报错与原因的对应关系：

| 报错                                             | 原因                     | 处理                                                     |
| ------------------------------------------------ | ------------------------ | -------------------------------------------------------- |
| 「图片过大，请选择 2MB 以内的 PNG、JPG 或 WebP」 | 文件超过 2MB 限制        | 压缩图片（降低分辨率/画质）后重试                        |
| 「图片格式无效，请选择 PNG、JPG 或 WebP」        | 文件类型不在支持范围     | 转换为 PNG / JPG / WebP 后重试（不接受 GIF/BMP/HEIC 等） |
| 「图片读取失败」                                 | 文件损坏或浏览器读取异常 | 重新导出/另存图片后重试                                  |
| 「请选择 OCR 模型和图片」                        | 下拉或图片未选择即提交   | 先选模型与图片再点「运行 OCR」                           |

### 步骤 3：排查识别乱码与结果偏差

1. 图片质量是乱码主因：优先排查模糊、倾斜、低分辨率、光线不均、反光与阴影；改善拍摄后重新识别。
2. 识别不稳定时以多次识别中较优结果为准，并**逐项人工核对**再使用。
3. 多页/长文档分页处理，避免单张超限与内容过密。
4. 双语或特殊字体（手写体、艺术字）识别准确率天然偏低，属于模型能力边界，结果务必人工核对。

### 步骤 4：排查连接与网络

1. 在「AI 连接」对 OCR 连接执行「测试」：返回「已连通 · {latency}ms · {model} …」即连接正常；失败按错误核对 Base URL、模型名与密钥。
2. 确认网络/代理未拦截到供应商端点；本机环境确认后端已启动。
3. 模型不存在类报错：换用准确模型标识并确认该模型支持图片输入与 OCR 能力。

## 修复与恢复

| 症状              | 直接修复动作                                              |
| ----------------- | --------------------------------------------------------- |
| 没有可用 OCR 模型 | 启用连接 / 补密钥 / 勾选 OCR 能力 / 新增带 OCR 能力的连接 |
| 图片过大          | 压缩到 2MB 以内（PNG/JPG/WebP）                           |
| 图片格式不支持    | 转换为 PNG/JPG/WebP 后重试                                |
| 识别乱码          | 改善拍摄质量（清晰、端正、均匀光线）后重新识别            |
| 连接失败          | 修正 Base URL/模型名/密钥后测试连接；确认网络可达         |
| 结果偏差          | 人工核对并修正后再进入业务数据；以多次识别较优结果为准    |

## 升级与收集信息

仍失败时，记录以下信息反馈到帮助中心「OCR」：

- **request id** 与报错原文。
- 图片格式、大小（字节）、分辨率；上传失败或识别失败的具体步骤。
- 使用的 OCR 连接与模型（不含密钥）、发生时间。
- **不要把含敏感信息的原图直接粘贴到公开渠道**；需要提交样本时先脱敏或使用无敏感内容样图。

## 验证结果

- OCR 模型下拉出现候选，选择图片后「运行 OCR」成功返回提取文本（`{provider} · {model} · {latency}ms · Token N`）。
- 识别文本与图片内容一致，乱码消除；上传恢复正常。
- 识别文本经人工确认后进入业务数据；预览过程未写入任何正式 OCR 记录。

## 常见问题

**症状：下拉框根本没有模型可选。**
可能原因：没有启用 + 已设密钥 + 具备 OCR 能力的连接。
排查与修复：按步骤 1 逐项核对；OCR 能力必须在模型级别勾选。

**症状：同一张图识别结果不稳定。**
可能原因：模型输出波动或图片质量处于临界。
排查与修复：提高图片质量重试；以多次识别中较优结果为准并人工核对。

**症状：提示 OCR 模型不存在。**
可能原因：模型名错误或该模型不支持图片识别。
排查与修复：配置独立 OCR 模型连接并使用准确模型标识；参考「配置 OCR 识别」。

**症状：识别结果数字/金额错误。**
可能原因：图片模糊或压缩过度。
排查与修复：使用原图质量重试；金额、日期等关键字段必须人工核对，不以识别文本为最终依据。

**症状：OCR 输出不是结构化结果。**
可能原因：未使用结构化提取场景（内置 profile：会议纪要、行动事项表、里程碑清单、风险登记册、需求清单）。
排查与修复：确认使用场景选择；结构化提取是独立能力，不与裸文本识别混淆。

## 安全与限制

- **人工确认边界**：识别结果不自动写入业务字段，必须人工确认；OCR 预览不写正式记录。
- **授权边界**：真实 OCR provider 接入属条件性外部动作，需用户明确授权；未授权时以预览形态呈现。
- 识别内容按组织隔离处理；不含敏感信息的图片才可用于升级反馈。
- 密钥与敏感图片不进入帮助文档与导出内容。
