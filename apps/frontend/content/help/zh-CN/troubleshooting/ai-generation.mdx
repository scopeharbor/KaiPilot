# AI 生成中断与失败

AI 快速创建（一句话建项）的草案生成中断、生成失败、流式断流或校验不通过时，先按本页识别失败形态并恢复。**AI 生成的全部内容只是草案，必须人工确认后才落库**——这条边界在生成、失败、恢复的每个环节都不变。

## 适用范围

- **适用角色**：`member`（可触发分析/生成，不能确认导入）、`project_manager`（有 `ai:confirm` 但无 `project:create`，同样不能完成导入）、`org_admin`（同时具备 `ai:confirm` 与 `project:create`，是当前可确认导入的角色）、`system_admin`（哨兵放行）；`external_collaborator` 与 `readonly_observer` 无任何 AI 触发权限。
- **所需权限**：页面级门控 `ai:trigger`（`/ai-create` 可直接访问）；**确认导入需要 `ai:confirm` 且 `project:create` 两者兼备**——当前矩阵下仅组织管理员与系统管理员可真正导入。
- **适用版本**：free / team / enterprise。

## 开始之前

- AI 生成基于 SSE 流式响应；弱网、代理与长连接中断都可能造成断流，断流后可从上次进度续跑（见步骤 4）。
- 输入约束：项目描述 10–4000 字；不要在输入中包含身份证号、手机号、客户隐私等敏感信息。
- 红线：生成阶段零正式落库，唯一写正式表的入口是人工「确认导入」。

## 症状识别

- **生成中断**：进度停在某一步不再前进，或健康徽章变为「连接暂时停滞 / 需要重试」。
- **生成失败**：出现「草案生成失败」面板，含失败阶段、原因码与脱敏错误摘要。
- **流式断流**：实时输出面板只出现一部分内容就停止。
- **校验不通过**：审查页提示「校验未通过，禁止确认导入」或「当前草案不可确认导入」。
- **兜底生成**：生成来源显示「Fallback / 离线结果」，或模型选择器显示「未配置草案模型，使用系统兜底」。
- **预算耗尽**：组织预算超限提示（「预算已超限 / 预算阻断」）。

## 排查步骤

### 步骤 1：识别「兜底（mock/fallback）生成」而不是误判为故障

未配置可用草案模型时，产品会走系统兜底并**显式标注**，这不是错误：

| 标识位置               | 显示内容                                                                                                | 含义                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 模型选择器             | 「未配置草案模型，使用系统兜底」                                                                        | 组织内没有启用且具备 `project_draft`/`chat` 能力的连接 |
| 审查页「生成来源」卡   | 「生成来源：Fallback / 离线结果」/「真实模型结果 · 请求策略 X · 生效策略 Y」「请求模型 X · 响应模型 Y」 | 区分兜底产物与真实模型产物                             |
| 生成来源卡「阶段产物」 | 「{章程与范围…}：已完成 \| 失败 · 工具 n/2」                                                            | 各阶段执行结果逐段列出                                 |
| 工作台演示模式         | 「当前是本机演示，回答来自固定示例」                                                                    | 宿主声明的演示形态，不读写任何数据                     |

处理：兜底生成物**结构可用但质量受限**，且通常被校验规则标记为不可确认导入（`HL-010` 等 blocking）——这属于反幻觉红线的正常闸门。要获得可导入的真实草案，先在「设置 → AI 连接」配置并启用一个具备 `project_draft`（或 `chat`）能力的连接，然后返回上下文重新生成。

### 步骤 2：按失败面板读取「失败阶段 + 原因码」

草案生成失败时会出现「草案生成失败」面板，按以下结构读取：

| 面板元素     | 内容                                                                   | 读取方法                                                       |
| ------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| 失败阶段     | `章程与范围 / WBS 与任务 / 排期与依赖 / 资源、风险与验收 / 一致性复核` | 定位是哪一步失败；审查页「阶段产物」也会显示各阶段 已完成/失败 |
| 原因码       | `原因码：{reasonCode}`（等宽 chip）                                    | 记录该码用于升级排查；原因码是服务端生成事件返回的机器可读标识 |
| 脱敏错误摘要 | path / code / message 列表                                             | 已脱敏的失败明细，可截图反馈，不含密钥与原始内容               |

常见服务端失败文案：

- 「生成服务繁忙，请稍后重试。」——供应商繁忙或限流，稍后重试。
- 「草案生成失败，请稍后重试或调整输入。」——生成中途失败，重试或缩小输入范围。
- 「后台生成任务已中断，请重新生成草案。」——后台任务被中断（服务重启、超时等），需要重新生成。

操作：面板提供「重试」与「返回上下文」；**重试会开始新的生成尝试，你之前提供的信息会保留**（无需重新做澄清）。

### 步骤 3：核对连接、余额与预算

1. 「设置 → AI 连接」测试连接：确认启用、密钥有效、模型名准确；失败表现（401/404/超时）与修复见「Copilot 不可用」与「配置 AI 连接」。
2. 余额/配额：供应商账户余额不足会被拒绝；充值或切换备用连接。
3. 组织预算：编译器运行摘要显示「预算警告 / 预算已超限 / 预算阻断」时，阻断态**没有绕过按钮**（红线），需联系组织管理员调整预算后再生成。

### 步骤 4：断流恢复（续跑）

1. 进度停住时先看健康徽章：`实时连接 / 生成用时较长 / 连接暂时停滞 / 正在恢复连接 / 正在同步进度 / 需要重试`。
2. 暂时停滞会被自动恢复：SSE 静默超过 20 秒触发看门狗，前端自动重连（最多 3 次，退避 1s / 2s / 4s）；重连期间提示「进度连接暂未收到新数据，正在尝试恢复连接。」
3. 自动恢复失败：提示「进度无法自动恢复，需要您操作重试。」，出现「继续接收进度」「重试生成」「重新生成」按钮。
4. **刷新页面可续传**：进度游标保存在 `sessionStorage`（key `aiproj-ai-draft-progress-cursor-v1`，24 小时有效，只存低敏标识）；刷新后自动从上次位置继续，提示「进度连接已中断，可从上次位置继续。」
5. 拆分输入：超长需求拆为更小范围重试，降低单次生成时长；规避弱网环境的长时间生成。

### 步骤 5：处理校验不通过（反幻觉闸门）

审查页会把校验结果分层展示，**blocking 校验是禁止确认的硬闸门**：

| 校验层级         | 展示                                                           | 处理                                       |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------ |
| blocking（硬性） | 「校验未通过，禁止确认导入」「当前草案不可确认导入」+ 原因列表 | 不能导入；按原因修正（行内编辑）或重新生成 |
| warning（警告）  | 「校验警告，建议人工检查」+ 确认对话框                         | 人工检查后「确认」才能继续导入             |
| info（提示）     | 「校验提示」+ `ruleId` 灰 chip                                 | 一般信息，不阻断                           |

规则编号速查（以 `HL-001~HL-010` 与 `VE-001~VE-012` 为准，不臆造规则名）：HL 阶段 `HL-001/002/003/006/007/008` 为 blocking，`HL-004/009/010` 为 warning，`HL-005` 为 info；VE 阶段 `VE-001/002/010` 为 blocking，其余为 warning/info。部分规则（如 `HL-002/004/006/007/008/009`）可自动修复，修复差异会以「自动修正差异」卡展示（path + 修正前/后 + reason），人工核对后按正常流程确认导入。

## 修复与恢复

| 症状                      | 直接修复动作                                                     |
| ------------------------- | ---------------------------------------------------------------- |
| 兜底生成 / 无法确认导入   | 先配置可用草案模型连接再重新生成；兜底草案不可确认导入属预期闸门 |
| 生成失败（带阶段+原因码） | 记录原因码；「重试」或「返回上下文」调整输入后重试               |
| 断流                      | 等待自动重连；失败后点「继续接收进度」或刷新页面自动续传         |
| 预算/余额不足             | 联系组织管理员检查预算与供应商账户；切换备用连接                 |
| 校验不通过                | 按 blocking 原因修正或重新生成；warning 人工确认后才可导入       |
| 反复中断                  | 拆分输入、切换模型、改善网络后再试                               |

## 升级与收集信息

仍失败时，记录以下信息反馈到帮助中心「AI 生成」：

- **request id** 与生成时间。
- **失败阶段 + 原因码**（面板原文）、中断点位置、输入概要（不含敏感数据）。
- 生成来源标识（Fallback / 真实模型）、使用的模型连接摘要（不含密钥）。
- 校验不通过时附规则编号（`HL-xxx` / `VE-xxx`）与原因摘要。

## 验证结果

- 生成流程完整跑完，进入草案审查；中断场景能通过续跑/重试恢复。
- 你能从「生成来源」卡明确识别本次生成是兜底还是真实模型产物。
- 任何生成内容（含失败重试）都未在你「确认导入」前写入正式项目。

## 常见问题

**症状：进度到一半卡住不动，页面没报错。**
可能原因：SSE 断流或网络抖动（静默超时 20 秒触发看门狗）。
排查与修复：等待自动重连（最多 3 次）；断连后点「继续接收进度」或刷新页面从上次位置续传；仍失败参考「流式进度不更新（SSE）」。

**症状：审查页提示「校验未通过，禁止确认导入」。**
可能原因：草案命中 blocking 校验（日期逻辑、依赖环路、完整性等），或草案来自兜底生成。
排查与修复：查看校验原因与自动修正差异；修正后重试；兜底草案请先配置真实模型连接。

**症状：提示预算或配额不足。**
排查与修复：联系组织管理员检查组织预算与供应商账户；切换备用连接后重试；预算阻断无绕过入口。

**症状：每次生成长文本都会断。**
可能原因：单次流式时长超过代理空闲超时，或模型响应过慢。
排查与修复：拆分输入、切换模型、改善网络（放行长连接）后重试。

**症状：页面提示「后台生成任务已中断」。**
可能原因：后台生成任务被中断（服务重启/超时），无法续传。
排查与修复：点「重新生成草案」；之前的输入信息会保留，草案仍需人工审查确认。

## 安全与限制

- **AI 只建议、不自动执行**：生成阶段零正式落库；唯一写正式表入口是人工「确认导入」（需 `ai:confirm` 且 `project:create`，当前为组织管理员/系统管理员）。
- **反幻觉红线**：HL-001~HL-010 与 VE-001~VE-012 校验约束生成质量，blocking 一律禁止确认导入。
- 生成上下文按组织隔离；跨组织草案一律 `RESOURCE_NOT_FOUND`。
- 进度游标只存低敏标识（sessionStorage，24h）；不把含敏感信息的输入与密钥写入文档、日志或聊天。
