# 项目视图总览：六种视图与共享数据模型

一个项目内提供六种视图观察**同一套任务数据**：看板（Kanban）、列表（List）、甘特图（Gantt）、日历（Calendar）、时间线（Timeline）与 WBS（工作分解结构）。切换视图不改变数据；专业入口与直觉入口共享同一个后端数据模型，不会为某个视图另建数据。

所有视图中的写操作（拖动、改期、状态流转、删除）都会经过状态机校验、行级权限判定与审计记录。凡涉及排程类的修改，甘特图一律采用「预览 → 人工确认 → 写入」的流程——确认前不会落库。

## 适用范围

| 角色                    | 查看视图     | 主要写操作                                                                |
| ----------------------- | ------------ | ------------------------------------------------------------------------- |
| `system_admin`          | 全部六种视图 | 系统哨兵权限，全放行                                                      |
| `org_admin`             | 全部六种视图 | 全部写操作（含 WBS 结构调整、项目级管理）                                 |
| `project_manager`       | 全部六种视图 | 全部写操作（含 WBS 结构调整）                                             |
| `member`                | 全部六种视图 | 可更新**自己负责**的任务；可创建/变更状态/删除里程碑；无 WBS 结构调整权限 |
| `external_collaborator` | 全部六种视图 | 仅可更新自己负责的任务                                                    |
| `readonly_observer`     | 全部六种视图 | 无写操作，纯只读                                                          |

六种视图的查看门槛并不完全一致（看板/列表/日历需要 `task:view`，时间线需要 `project:view`），但四个基础角色（`member` 及以上、`external_collaborator`、`readonly_observer`）都同时具备这两个权限，因此**六种视图对项目内所有角色均可查看**——差别全部体现在写操作按钮上。

## 核心概念：六种视图的定位

| 视图   | 入口 Tab | 定位                                                 | 写操作特点                                                                             |
| ------ | -------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 看板   | 看板     | 日常执行：四列投影六种任务状态，拖动卡片流转状态     | 拖动必须走六态状态机与行级权限，拖入「其他」列需显式选择真实状态                       |
| 列表   | 列表     | 专业密集工作区：高密度表格、多条件筛选、批量操作     | 排序/筛选只影响呈现；批量操作逐项授权、部分成功                                        |
| 甘特图 | 甘特图   | 排程/依赖/关键路径：任务条 + 依赖线 + 里程碑 + 基线  | 改期、依赖、进度、里程碑日期全部「预览 → 人工确认」；建立依赖后任务日期不会自动改变    |
| 日历   | 日历     | 截止日与完整排程两种模式的日历视图                   | 截止日模式拖拽直接写入截止日（无预览确认）；排程模式拖拽先乐观预览、失败回滚           |
| 时间线 | 时间线   | 只读项目记忆：按时间回看任务、里程碑、风险与变更动态 | 纯只读，不用于排程编辑                                                                 |
| WBS    | WBS      | 工作分解结构树：自上而下拆解范围                     | 编号由系统自动维护；根节点锁定；层级最多 20 层；删除子节点时其直接子节点提升为一级节点 |

## 视图与权限

后端按视图与动作收敛权限（参考 `projects.projects-list-and-create` 了解项目本身的创建与管理权限）：

| 动作                     | 所需权限                                              | 说明                                                                                      |
| ------------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 查看看板/列表/日历       | `task:view`                                           | 页面级守卫，无权限时显示「你没有查看…的权限」                                             |
| 查看时间线               | `project:view`                                        | 时间线是项目级只读记忆                                                                    |
| 查看甘特图/WBS           | `task:view`（数据接口门槛）                           | 无页面级守卫，写按钮按权限渲染                                                            |
| 拖动看板/日历改期        | `task:update`，或 `task:update:self` 且为本人负责任务 | `member` 只能拖动自己负责的任务；无权限的卡片不可拖动                                     |
| 甘特图改期/进度/保存基线 | `task:update`                                         | 无该权限时工具栏只有「选择/基线」两种模式，并显示「只读模式：无编辑权限」                 |
| 甘特图建立依赖           | `task:update` 或 `task:update:self`                   | 依赖权限单独判定                                                                          |
| 管理里程碑               | `milestone:create/update/delete`                      | **`member` 也拥有**；`external_collaborator` 与 `readonly_observer` 只有 `milestone:view` |
| 调整 WBS 结构            | `wbs:create/update/delete/move`                       | 仅 `org_admin` / `project_manager`；`member` 只有 `wbs:view`                              |

## 开始之前

- 已登录并进入某个组织（无组织时页面显示「请先选择组织」）。
- 已进入任意项目（需要 `project:view` 权限；创建方法见「创建第一个项目」）。
- 建议先创建几个带状态的示例任务，再对照各视图观察数据同源效果。

## 操作步骤

### 步骤 1：打开视图切换器

进入项目详情页，在顶部项目头下方找到视图切换器（样式为一组 Tab）；你会看到固定顺序的六个基础 Tab：**看板 / 列表 / 甘特图 / 日历 / 时间线 / WBS**。Tab 之后是分隔线与「健康与风险」Tab（v3 功能），再之后是「我的视图」自定义视图列表（如已配置）。

### 步骤 2：逐个查看六种视图

1. 点 **「看板」**：任务按四列（待处理/进行中/已完成/其他）排列，可拖动卡片流转状态。
2. 点 **「列表」**：同一批任务以高密度表格呈现，可多条件筛选、多列排序、批量操作。
3. 点 **「甘特图」**：任务以时间条呈现，含依赖连线与关键路径，可做排程推演。
4. 点 **「日历」**：任务按截止日（默认）或完整排程落入日历格。
5. 点 **「时间线」**：按时间分组回看任务、里程碑、风险与变更动态。
6. 点 **「WBS」**：查看工作分解树，编号由系统自动维护。

### 步骤 3：验证数据同源

在任一视图中修改任务（例如在看板把任务拖到「进行中」，或在列表修改截止日），切换到其他视图：你会看到同一任务的状态、起止日期、负责人等信息在其他视图中同步反映。视图切换不触发整页重载，切换后保持当前筛选条件（筛选条件各自记录在 URL 或组件状态中）。

## 验证结果

- 你能在六种视图之间自由切换，且同一任务的数据（状态、起止日期、负责人、进度）在所有视图中保持一致。
- 拖拽/编辑操作按你的角色权限生效：有权限的操作立即生效，无权限的操作被禁用或提示。
- 只读角色（`readonly_observer`）能进入全部六种视图，但看不到任何写操作按钮。
- 甘特图的排程类修改在点击确认前不会写入正式排期。

## 常见问题

### 症状：某个视图打开后被提示「你没有查看…的权限」

- **可能原因**：当前角色缺少对应视图的查看权限（如时间线需要 `project:view`）。
- **检查**：你当前所在组织与项目角色。
- **修复**：联系项目经理或 org_admin 调整项目角色后重试。
- **仍失败时**：记录角色、视图名称与操作时间，到「故障排查」查找或联系支持。

### 症状：视图中看不到任务

- **可能原因**：视图的筛选条件（状态/负责人/关键词等）限制了结果，或项目还没有任务。
- **检查**：视图顶部的筛选条件是否为空；到列表视图查看项目任务总数。
- **修复**：清空筛选条件；在列表或看板快速新建任务。
- **仍失败时**：记录项目 id 与 request id 反馈。

### 症状：甘特图与日历显示的日期不一致

- **可能原因**：甘特图显示的是任务的**起止日期**，日历截止日模式显示的是**截止日**（`end_date`）——两者是不同的字段。
- **检查**：任务详情中的「计划开始/计划结束」与「截止日期」。
- **修复**：在日历切换到「排程」模式可看到与甘特图一致的完整日期区间。
- **仍失败时**：记录两个视图的截图与任务 id 反馈。

## 限制与安全边界

- **数据模型唯一**：六种视图是同一数据模型的不同投影，不会为直觉入口另建后端；「简单」是前端隐藏，不是后端阉割。
- **操作全经过服务端判定**：界面隐藏按钮不等于后端无能力，所有写操作由服务端 Policy/RBAC 复判。
- **组织级隔离**：所有项目与任务查询自动附加当前组织过滤；跨组织的项目 id 一律返回 404（不泄露存在性），不能跨组织共享项目数据。
- **AI 只建议、不自动执行**：六视图内没有任何 AI 自动落库动作。「向 Copilot 询问」只打开 Copilot 面板，不写入数据；AI 生成的项目草案必须人工审查确认后才成为正式项目。
