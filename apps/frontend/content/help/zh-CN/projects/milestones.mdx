# 管理项目里程碑

里程碑是项目关键节点的标记（如「需求冻结」「核心功能上线」）。它们挂在**甘特图工具栏**的「里程碑」抽屉中管理，并以**菱形标记**呈现在甘特时间轴上。里程碑与任务相互独立：它的「有风险 / 已逾期」由系统按目标日期自动推导，而「已达成」需要人工确认。

## 适用范围

| 角色                                | 查看里程碑 | 创建 / 编辑 / 删除                   |
| ----------------------------------- | ---------- | ------------------------------------ |
| 项目经理（project_manager）         | ✅         | ✅                                   |
| 组织管理员（org_admin）             | ✅         | ✅                                   |
| 成员（member）                      | ✅         | ✅（成员也可增删改，与任务权限不同） |
| 外部协作者（external_collaborator） | ✅ 只读    | ❌                                   |
| 只读观察者（readonly_observer）     | ✅ 只读    | ❌                                   |

> 权限标识：`milestone:view`（查看，缺失时甘特图工具栏「里程碑」入口**整体隐藏**）、`milestone:create` / `milestone:update` / `milestone:delete`（增删改）。只有查看权限的角色进入抽屉会看到顶部提示「当前角色为只读，仅可查看里程碑。」，且无新建/编辑/删除按钮。
>
> 系统管理员是平台级角色，项目域实际权限取决于部署时的角色授予，不在本表范围。

## 开始之前

- 项目已进入[甘特图视图](/help/articles/projects.gantt)（视图 Tab「甘特图」）。
- 当前账号持有 `milestone:view`（否则工具栏上看不到「里程碑」入口）。
- 本机演示环境（默认组织）的种子数据**不创建任何里程碑**：新项目打开甘特 → 里程碑抽屉首次即为「暂无里程碑」空态，可从零开始练习。

## 操作步骤

### 步骤 1：打开里程碑管理抽屉

1. 在甘特图页面顶部工具栏左侧点击**「里程碑」**按钮（Flag 图标）。
2. 你会看到抽屉标题「里程碑管理」，描述为「管理项目里程碑；有风险 / 已逾期由系统按目标日期自动提示，达成需人工确认。」

### 步骤 2：创建里程碑

1. 抽屉为空态（「暂无里程碑」）时，点击**「添加里程碑」**（只读角色无此按钮）。
2. 在表单中填写字段：

| 字段         | 必填 | 约束           | 说明                                             |
| ------------ | ---- | -------------- | ------------------------------------------------ |
| 名称         | ✅   | 1–255 字符     | placeholder「如：需求冻结」                      |
| 目标日期     | ✅   | `YYYY-MM-DD`   | 作为系统推导「已逾期 / 有风险」的依据            |
| 状态         | ✅   | 见下方状态说明 | 下拉仅 `未开始` / `计划中` / `已达成` 可人工选择 |
| 描述（可选） | ❌   | ≤ 2000 字符    | 补充说明                                         |

![里程碑管理抽屉：规则说明、三条里程碑列表（需求基线冻结/核心功能上线/项目验收），每条含状态徽章、目标日期与编辑/删除操作。](assets/milestone-manager.png)

3. 状态选择**「已达成」**时，提交按钮会变为**「确认达成」**（提示这是一次人工确认）；其他状态时按钮为「创建」/「保存」。
4. 点击提交后，新里程碑出现在列表（状态徽章 + 目标日期，无日期显示「未设目标日期」），甘特时间轴上出现按状态着色的菱形标记。

> [!IMPORTANT]
> **有风险 / 已逾期是系统推导的展示态，表单中不可直接选择**（编辑历史遗留的推导态里程碑时会保留该选项以防丢值）。**已达成只能人工确认**：确认达成会写入 `MILESTONE_ACHIEVED` 审计事件，且该状态不会被系统改写。

### 步骤 3：查看与理解状态推导

里程碑有五种状态，其中两种由系统推导：

| 状态   | 中文徽章          | 来源                                   |
| ------ | ----------------- | -------------------------------------- |
| 未开始 | 未开始（neutral） | 人工选择                               |
| 计划中 | 计划中（primary） | 人工选择                               |
| 有风险 | 有风险（warning） | 🔵 系统推导：项目预测完工日 > 目标日期 |
| 已达成 | 已达成（success） | 人工确认（写审计）                     |
| 已逾期 | 已逾期（danger）  | 🔵 系统推导：目标日期 < 今天           |

推导规则（纯函数，只影响展示、不自动改写持久化状态）：

- **已逾期**：目标日期早于今天；系统**不会**自动把里程碑改成「已逾期」的持久化状态，下次进入仍是原状态；
- **有风险**：项目的「预测完工日」晚于目标日期——预测完工日以**未完成任务的最晚结束日期**作为轻量代理，不依赖关键路径计算；
- **已达成**：恒为人工状态，永不被系统覆盖。

> [!WARNING]
> 里程碑逾期 / 到期的**通知发送函数已具备，但当前没有接入任何调度任务，本版本不会自动发送通知**。请在管理列表中自行关注「已逾期」「有风险」徽章，或依靠目标日期列人工判断。

### 步骤 4：编辑与删除里程碑

1. **编辑**：点击条目右侧铅笔（编辑）按钮，修改名称、目标日期、状态或描述后保存。
2. **删除**：点击垃圾桶图标 → 行内出现「确认删除「{名称}」？」+「取消」「删除」，需二次点击确认；删除不询问是否删除相关甘特标记（标记随里程碑一并消失）。
3. 确认后列表更新；甘特时间轴上的对应菱形同步移除。

### 步骤 5：在甘特图中调整里程碑日期

1. 在甘特时间轴上**拖动里程碑菱形标记**到新的日期。
2. 弹出「确认里程碑日期调整」对话框：文案「仅调整里程碑目标日期，确认前不会写入。任务、依赖与基线不会因此改变。」，并列出字段：里程碑名称 / 调整前日期 / 调整后日期。
3. 点击**「确认调整」**才写入；点击取消则不生效。

> [!NOTE]
> 调整里程碑目标日期**只改里程碑本身**：不改变任何任务日期、依赖关系，也不影响项目基线。甘特图拉取里程碑为全量列表（不分页），项目内里程碑都会渲染在时间轴上。

## 验证结果

- 新里程碑出现在抽屉列表与甘特时间轴（菱形按状态着色）。
- 把目标日期设为今天之前并刷新后，该里程碑显示「已逾期」徽章（推导态）。
- 把目标日期设为早于「未完成任务的最晚结束日期」的某一日，该里程碑显示「有风险」徽章。
- 人工确认「已达成」后，徽章变为绿色「已达成」；审计日志出现 `MILESTONE_ACHIEVED`。
- 无 `milestone:view` 的角色在甘特工具栏看不到「里程碑」入口。

## 常见问题

**症状：状态下拉里选不了「有风险」「已逾期」。**
可能原因：这两个状态是系统推导的展示态，不允许人工直选。
检查：对照推导规则（预测完工日 vs 目标日期）。
修复：调整目标日期或推进任务排期，系统会自动重新推导；编辑历史遗留的推导态时选项会被保留以防丢值。

**症状：里程碑逾期了但没有收到任何通知。**
可能原因：当前版本没有接入自动通知调度（发送函数未挂载任何调用方）。
检查：抽屉列表中的「已逾期」红色徽章与目标日期列。
修复：以列表徽章与目标日期列为准，自行跟进；不要依赖系统推送。

**症状：拖动菱形后任务日期没变。**
可能原因：设计如此——里程碑调整只改目标日期。
检查：确认对话框文字「仅调整里程碑目标日期，确认前不会写入。任务、依赖与基线不会因此改变。」。
修复：如需联动任务排期，请在甘特图直接调整任务条或依赖。

**症状：点「确认达成」后状态又被系统改了。**
可能原因：不会发生——已达成是人工确认的 sticky 状态，系统推导永不改写它（且本次确认已写 `MILESTONE_ACHIEVED` 审计）。
检查：刷新列表确认状态徽章；如仍异常，记录里程碑 id 与操作时间反馈。

**症状：工具栏上看不到「里程碑」入口。**
可能原因：当前账号没有 `milestone:view` 权限（入口整体隐藏）。
检查：角色是否为外部协作者/只读观察者或更低权限。
修复：由项目经理调整项目角色后重试。

**症状：通过列表直接访问他人的里程碑提示 404。**
可能原因：组织隔离——跨组织的里程碑列表/详情一律表现为资源不存在。
修复：确认访问的项目与登录组织一致。

## 安全与限制

- **系统推导只影响展示**：有风险/已逾期的推导不自动改写持久化状态，也不自动改任务日期。
- **达成需人工确认**：`已达成` 只能人工选择并写审计；这是里程碑层面的「人工确认边界」，与 AI 落库需人工确认属于同一原则。
- **不自动通知**：逾期/到期通知生成函数当前未接入任何定时任务，文档不承诺通知能力。
- **成员可管理**：成员（member）角色持有里程碑创建/更新/删除权限（与任务的 `task:update:self` 限制不同）。
- **组织隔离**：跨组织访问里程碑为 404。
- **AI 边界**：里程碑无自动执行路径；所有写入经普通 API + 审计。
