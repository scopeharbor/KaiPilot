# 创建第一个项目

本教程带你走完「一句话需求 → AI 草案 → 人工审查 → 正式项目」的完整路径，预计 10 分钟。全程遵循同一条红线：**AI 只建议，任何内容都必须经你确认后才落库。**

## 适用范围

- **适用角色**：成员（`member`）、项目经理（`project_manager`）、组织管理员（`org_admin`）、系统管理员（`system_admin`）。
- **所需权限**：`project:create`（默认成员及以上角色可创建项目）。
- **适用环境**：本机开发（`pnpm dev`）与线上环境的流程一致。

## 开始之前

1. **已登录并处于目标组织**：新项目会创建在当前组织下。未登录时，访问任意受保护页面都会先进入登录页：

   ![登录页全貌：左侧品牌区（Logo 与「回到你的项目工作台」），右侧「安全登录」表单（邮箱、密码、登录按钮），下方为 Google 登录区块。](assets/login-page.png)

   登录方式细节（邮箱密码 / Google、回跳与锁定机制）见[登录与账号](/help/articles/getting-started.login-and-accounts)。

2. **确认右上角组织**：登录后检查组织切换器，确保显示的目标组织（如「我的默认组织」）。项目创建后归属该组织，其他组织成员不可见。
3. **建议先配置 AI 连接**：组织配置可用的 AI 连接后，草案生成更稳定（见[配置 AI 连接](/help/articles/ai.configure-ai-connections)）。未配置时生成路径与草案可否确认导入，以草案页顶部的生成来源与校验提示为准（见「常见问题」）。
4. **准备一句话需求**：包含目标、周期与关键约束，例如「做一个为期 3 个月的市场活动网站，含报名与后台管理」。

## 操作步骤

### 步骤 1：进入 AI 快速创建

登录后进入仪表盘（`/dashboard`），点击区块下方的 **「AI 快速创建项目」** 按钮，或左侧导航「核心功能 → AI 快速创建」，浏览器打开 `/ai-create`。

仪表盘顶部是 AI Copilot 操作入口与导航按钮，下方是项目概览、最近项目与团队动态：

![登录后仪表盘：顶部问候语与顶栏工具（搜索、通知铃铛、Copilot、外观、用户菜单），主体为 AI Copilot 操作入口（状态「可用」、输入框与「打开 Copilot」按钮），下方为「也可以直接前往」三条导航按钮。](assets/dashboard-copilot-ready.png)

### 步骤 2：输入一句话需求

在「先把项目意图说清楚」输入框中填写目标描述。参考参数：

| 要素     | 说明                             | 示例                              |
| -------- | -------------------------------- | --------------------------------- |
| 目标     | 要交付什么、解决什么问题         | 做一个市场活动网站                |
| 周期     | 期望的起止时间或工期             | 为期 3 个月                       |
| 关键约束 | 预算、范围边界、必须上线的时间点 | 含报名与后台管理、10 月 15 日上线 |

输入完成后你会看到「开始分析」按钮；如需基于搜索结果补全行业信息，可开启「允许本次使用网页搜索」（该开关默认关闭，是否可用取决于组织配置，见[联网搜索](/help/articles/ai.optional-web-search)）。

### 步骤 3：回答澄清卡片

系统会根据你的描述提出若干追问卡片（阶段式推进，例如 1/3、2/3）：

- 卡片右上标注**「必答」**时该项对生成质量影响较大；其余卡片可以跳过，跳过项按合理默认值处理。
- 卡片上展示 AI 的**置信度**与可选的**影响范围**选项，点选 chips 即可快速作答。
- 可直接点 **「采用 AI 建议：…」** 采纳推荐值，或用你自己的答案覆盖。

回答机制与技巧详见[需求澄清卡片](/help/articles/ai.clarification-cards)。

### 步骤 4：生成草案（真实流式进度）

澄清完成后点击 **「开始生成草案」**。生成开始时：

- 页面按模块逐项推进（章程、WBS、任务、依赖、风险等九个模块），每个模块有独立的进度条与完成状态，而不是一整块等待；
- 「AI 实时输出」面板随生成滚动输出内容；
- 生成过程中不要关闭页面；中断时已完成的进度会保留检查点，可重新发起继续生成（详见[AI 草案生成与审查](/help/articles/ai.generation-progress-and-review)）。

### 步骤 5：审查草案

生成完成后，草案区会展示：项目章程、WBS 结构、任务清单与依赖关系等区块。逐项核对：

| 检查项   | 核对内容                               |
| -------- | -------------------------------------- |
| 日期逻辑 | 结束日期不早于开始日期、里程碑顺序合理 |
| 依赖环路 | 任务 A 依赖 B 且 B 依赖 A 会被标出     |
| 验收标准 | 是否可衡量、可验证                     |
| 范围     | WBS 与任务是否覆盖你输入的全部目标     |

反幻觉检查（HL-001~HL-010）的发现会逐条列出；**校验未通过时，「确认导入」入口不可用**——这是产品红线「草案必须经审查」的正常状态，不是故障。

### 步骤 6：就地修正

对不满意的字段直接编辑（例如把上线日期改为「10 月 20 日」）。修改后页面会重新触发校验，你会看到校验状态提示同步更新。

### 步骤 7：导入为正式项目

确认规则校验与反幻觉检查全部通过后，点击 **「导入为正式项目」**。导入完成后页面跳转到项目详情。

### 步骤 8：验证项目内容

打开「项目」列表（`/projects`）：

1. 找到新项目（列表按组织隔离，只显示你有成员资格的项目）。
2. 进入项目详情页，顶部切换六种视图，确认 WBS 与任务与草案一致（视图说明见[项目视图总览](/help/articles/projects.views-overview)）。
3. 指派成员：在项目内「成员管理」中添加团队成员并分配项目角色，项目即可进入协作（见[邀请团队成员](/help/articles/getting-started.invite-your-team)）。

## 验证结果

- 项目出现在「项目」列表，可进入详情页查看任务 / WBS / 依赖。
- 草案审查期间没有任何字段被自动落库（AI 只建议）；导入按钮在检查未通过时不可用。
- 项目归属你当前选择的组织，其他组织成员不可见。

## 常见问题

**症状：AI 草案一直「生成中」没有进度。**
可能原因：AI 服务连接异常、模型配额不足或流式连接中断。
检查：打开「设置 → AI 连接」执行「测试连接」，确认是否返回成功（链接见[配置 AI 连接](/help/articles/ai.configure-ai-connections)）。
修复：切换可用模型后重试；已完成的模块进度会保留检查点，可重新发起继续生成。
仍失败时：记录错误面板中的 request id 与失败时间，到[故障排查 → AI 生成](/help/articles/troubleshooting.ai-generation)查找或提供给技术支持。

**症状：「导入为正式项目」按钮置灰或点击无反应。**
可能原因：规则校验（如日期逻辑、依赖环路）或反幻觉检查（HL-001~HL-010）存在未通过的 finding；或当前草案生成来源为系统兜底（未配置真实模型时），处于「不可确认导入」状态。
检查：草案页顶部的校验结果列表，逐条查看红色 finding；查看「生成来源」标注。
修复：按 finding 提示修改对应字段（如调整日期、解除环路依赖）后重新校验，或先配置可用的 AI 连接后重新生成草案。
仍失败时：截图校验结果并记录 request id，到[故障排查](/help/articles/troubleshooting.ai-generation)查找。

**症状：导入成功但项目列表里找不到。**
可能原因：右上角组织切换器当前不在项目所属组织。
检查：`/projects` 页顶部是否显示正确的组织名。
修复：切换到项目所属组织后刷新列表。
仍失败时：记录项目名称、组织名与 request id，联系组织管理员核对。

**症状：分不清「AI 快速创建」和「手动创建」。**
可能原因：两条入口在同一个新建项目页。
检查：项目列表页的「新建项目」弹窗中的两个选项。
修复：有清晰需求时用 AI 快速创建（本教程）；只有离线形成的完整结构（编号、层级、日期）时用手动创建。

## 安全与限制

- 草案必须通过规则引擎校验与反幻觉检查（HL-001~HL-010）才能转正式项目；校验未通过时禁止导入。
- AI 只建议：草案、修改建议都需要你人工确认后才落库，任何一步都不会自动写库。
- 组织级数据隔离：项目归属创建时的组织；涉及真实组织、预算、外部服务的操作遵循组织权限与服务端判定。
- 需求输入中的敏感信息（预算、客户名等）会随请求发送到配置的模型服务：请先确认组织选择的模型服务符合你的数据合规要求。
