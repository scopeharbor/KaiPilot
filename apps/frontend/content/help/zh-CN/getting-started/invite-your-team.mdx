# 邀请团队成员

把同事加入组织并分配角色，再为他们开放项目访问，让协作从「看得见」开始。本指南覆盖邀请前准备、角色选择、发送与接受、以及常见问题排查。

## 适用范围

- **适用角色**：组织管理员（`org_admin`）、系统管理员（`system_admin`）；组织负责人（owner）同样具备成员管理能力。
- **所需权限**：组织成员管理权限（无此权限时无法看到邀请入口）。
- **适用版本**：所有版本（free / team / enterprise）。

## 业务场景

| 场景                       | 推荐做法                                                 |
| -------------------------- | -------------------------------------------------------- |
| 新同事加入                 | 邀请为组织成员（member），再添加到具体项目并分配项目角色 |
| 外部协作者（供应商、顾问） | 加入项目时作为外部协作者，只授予该项目的访问范围         |
| 只读汇报（管理层）         | 邀请为组织访客（viewer）或项目的只读观察者               |

## 开始之前

1. **确认当前所在组织**：右上角组织切换器应显示目标组织；邀请只影响当前组织，跨组织互不可见。
2. **了解双层角色模型**：邀请时分配的是**组织角色**（控制能否进入组织），进入项目后还要分配**项目角色**（控制在该项目内能做什么）：

| 角色层   | 角色                  | 定位                                              |
| -------- | --------------------- | ------------------------------------------------- |
| 组织角色 | owner / org_admin     | 组织负责人 / 组织管理员：管理成员、连接与安全配置 |
| 组织角色 | member                | 组织成员：可被加入项目参与协作                    |
| 组织角色 | viewer                | 组织访客：只读查看组织内被授权的数据              |
| 项目角色 | project_manager       | 项目经理：管理项目计划（WBS/甘特/任务/依赖）      |
| 项目角色 | member                | 项目成员：执行任务、评论、上传附件                |
| 项目角色 | readonly_observer     | 项目只读观察者                                    |
| 项目角色 | external_collaborator | 外部协作者：仅访问被授予的项目                    |

完整的六角色说明见[账号、组织与角色](/help/articles/admin.accounts-organizations-and-roles)与[权限参考](/help/articles/reference.permissions)。

3. **确认受邀人已有账号**：邀请按邮箱把**已有账号**加入组织。开项没有自助注册页；对方还没有账号时，请实例管理员在部署机的 `apps/backend` 目录执行：

   ```bash
   node ace user:create --email 同事邮箱 --generate-password
   ```

   命令只新建普通账号、不修改已有账号，生成的密码只在终端显示一次，请转交对方并提醒登录后修改。配置了 Google 登录时，对方也可以先用 Google 登录一次。

## 操作步骤

### 步骤 1：进入组织成员管理

打开组织设置中的 **「成员」** 页（入口通常位于「组织」中心或「设置」内，具体位置随导航布局而定）；你会看到成员列表与邀请区。

### 步骤 2：填写邀请信息

在邀请区填写：

| 字段     | 必填 | 说明                                                     |
| -------- | ---- | -------------------------------------------------------- |
| 成员邮箱 | 是   | 受邀人的登录邮箱（须已有账号）                           |
| 组织角色 | 是   | 从上面「组织角色」表中按需选择（常见为 member / viewer） |

点击 **「邀请成员」**。

### 步骤 3：确认已加入

- 邀请成功后，该成员立即出现在成员列表中，并带有所选的组织角色。
- 对方用自己的账号登录后即可进入组织（登录方式见[登录与账号](/help/articles/getting-started.login-and-accounts)）。

### 步骤 4：把成员加入项目并分配项目角色

组织成员资格不等于项目访问权。进入目标项目详情页，打开 **「成员管理」**：

1. 添加成员（支持输入邮箱邀请）。
2. 分配项目角色（project_manager / member / readonly_observer / external_collaborator，按业务场景选择）。
3. 保存后，该成员即可看到项目数据，并按角色执行操作（如查看[看板](/help/articles/projects.kanban)、执行任务）。

## 验证结果

- 受邀人登录后能在组织成员列表中看到自己。
- 加入项目并分配角色后，成员能在项目视图（如[看板](/help/articles/projects.kanban)）看到任务并按其角色操作。
- 切换角色视角检查：只读观察者/外部协作者看不到编辑入口，服务端会拒绝其越权操作。

## 常见问题

**症状：点「邀请成员」后提示「该邮箱尚未注册」。**
可能原因：对方还没有账号。
检查：邮箱拼写是否与对方账号一致。
修复：请实例管理员执行 `node ace user:create --email 同事邮箱 --generate-password` 建立账号后再邀请；配置了 Google 登录时也可以让对方先用 Google 登录一次。
仍失败时：记录操作时间与邮箱，联系实例管理员核对。

**症状：新成员看不到项目。**
可能原因：已加入组织但未加入项目，或未分配项目角色。
检查：项目「成员管理」列表是否包含该成员及其角色。
修复：在项目详情页添加成员并分配项目角色；分配后成员即可看到项目数据。
仍失败时：收集成员列表截图与 request id，到[故障排查](/help/articles/troubleshooting.project-loading)查找。

**症状：找不到邀请入口。**
可能原因：当前角色没有成员管理权限。
检查：右上角角色标识，以及组织设置里可见的菜单项。
修复：联系组织管理员代为邀请，或先调整角色。
仍失败时：记录角色与操作路径，提交支持时一并提供。

## 安全与限制

- 组织级数据隔离：邀请只影响当前组织，跨组织互不可见。
- 权限判定在服务端：界面上看不到的入口，后端同样会拒绝；展示层过滤不是安全边界。
- 成员的角色变更、移除等操作请由组织管理员在成员管理中处理；只读角色不能修改任何项目数据。
